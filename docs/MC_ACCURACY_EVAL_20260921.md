# Grafly MC 판정 보강 및 전후 비교 — 2026-09-21

같은 질의 근거를 가진 후보를 연결 수만으로 확정하던 동작을 보류로 바꿨다.
MCP와 워크스페이스 조회도 보류 중에는 `top: 1`로 후보를 숨기지 않는다.
CLI, 단일 레포 MCP, 워크스페이스 MCP에서 실제 JS 소스를 인덱싱한 뒤 확인했다.

## 변경 범위

- `dist/circuit/judge.js`: 기존 순위 점수와 가중치를 유지한다. 1위와 이름·수식어·경로·종류·소스/테스트 구분·현재 폴더 근거가 같은 다른 후보가 있으면 연결 수 차이만으로 확정하지 않는다. 2위뿐 아니라 모든 후보를 검사한다.
- `dist/graph/traverse-cli.js`: 새 보류 사유를 표시한다. 근거 부족으로 보류할 때 점수 차가 임계값보다 작다는 잘못된 설명을 출력하지 않는다.
- `dist/mcp/tools.js`, `dist/graph/workspace.js`: CLI와 동일하게 보류된 후보를 모두 유지한다.
- 동점 후보의 출력 순위와 `circuit.top`은 기존처럼 참고 순위다. 보류 상태에서는 선택된 정답이나 확률을 의미하지 않는다. `confidence`는 계속 null이다.

MC Python `code_relation` 전체를 이식한 작업은 아니다. 그 변경의 오판 방지 원칙을
Grafly의 기존 JS 판단 경로에 적용했다. Python import 판정, MoreCoffee 본체,
HMJE, 압축 규칙, 외부 훅은 이번 수정 대상이 아니다.

## 처리시간과 출력량

실제 레포 200개 재생을 7회씩 측정했다. 아래 내부 처리시간은 심볼 해석과 판단만
포함하며 프로세스 시작, 파일 읽기, 결과 렌더링은 제외한다.

| 내부 처리시간 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 중앙값 | 1.2085 ms | 1.2054 ms |
| 95백분위 | 1.8446 ms | 1.8559 ms |
| 평균 | 1.1421 ms | 1.1514 ms |

두 실제 소스 재현 사례는 워밍업 후 경로별 9회씩 비교했다.
CLI 시간은 프로세스 시작을 포함한다. MCP는 도구 처리 함수 시간이며 RPC 전송은 제외한다.

| 사례·경로 | 중앙값 전 → 후 | 표시 후보 수 전 → 후 | 출력 바이트 전 → 후 |
| --- | ---: | ---: | ---: |
| 동일 근거·CLI | 381.08 → 373.64 ms | 2 → 2 | 1,761 → 1,761 |
| 동일 근거·MCP | 32.74 → 33.80 ms | 1 → 2 | 607 → 961 |
| 동일 근거·워크스페이스 MCP | 33.33 → 33.77 ms | 1 → 2 | 595 → 969 |
| 연결 수 차이·CLI | 358.33 → 365.44 ms | 1 → 2 | 7,531 → 8,012 |
| 연결 수 차이·MCP | 35.34 → 34.06 ms | 1 → 2 | 1,540 → 1,666 |
| 연결 수 차이·워크스페이스 MCP | 32.32 → 32.84 ms | 1 → 2 | 1,528 → 1,674 |

뚜렷한 속도 향상은 확인되지 않았다. 보류된 근거를 보존하면서 해당 결과의 출력량은
증가할 수 있다. 출력 바이트를 실제 LLM 입력 토큰이나 비용 절감으로 환산하지 않는다.
모델 답변 품질, 세션 압축률, 라이브 세션 교체는 이번 평가에서 측정하지 않았다.
